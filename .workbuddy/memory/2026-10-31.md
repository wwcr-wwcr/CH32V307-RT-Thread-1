# 2026-10-31

## 新增 task6：串口投屏（电脑画面 → 板子，16 色 1 秒 1 帧）

需求：菜单加第 6 个任务，用唯一的 uart1 把 PC 画面送下来显示，
重点是不能让缓存堆积，尽量上 DMA。方向确认：**电脑 → 板子**。
中途用户砍掉了声音（"扬声器输入的东西应该错了"），并要求"一秒一帧、每块尽量压缩、
看个大概就行"，于是改成 16 色方案。

### 实现要点（避免以后重复踩坑）
- 带宽事实：320x480 RGB565 整帧 300KB，921600bps 要 3.3s → 什么优化都不够。
  最终方案：**4bit 索引（16 色，每帧自适应调色板，32 字节）+ PackBits**。
  全屏 73.6KB 原始 → 实压 20~40KB → 0.2~0.5 秒一帧。
- 投屏区域 320x460，底部 20px 留状态栏（避免图块把文字覆盖）。
- uart1 复用三件事：关 RXNE（DATAR 只归 DMA）、静音 ch32_putc（否则 ASCII 污染二进制流
  且死等 TC）、改波特率到 921600。
- 接收链路：DMA1_Channel5 循环 512B + HT/TC/IDLE 中断 → 4KB 环形缓冲 → 状态机拆帧。
  满缓冲丢字节 + resync，中断里绝不等待。
- 显示：LCD 只允许 UI 线程写，所以解压（PackBits→4bit）在任务线程、查表还原 RGB565 在
  render()。图块队列 16 格 × 512B = 8KB，满了丢新块（10ms 吐 16 块 = 1600 块/秒）。
- PC 端量化用 Pillow 的 `img.quantize(16, MEDIANCUT)`，**必须关 dither**，
  否则抖动噪点会把 PackBits 压缩率毁掉。
- 每帧整屏重发（不再做块级差分）：协议简单、不会出现"改了没发导致永久残块"的坑。

### 踩过的坑
- 块级差分时 `prev` 在 encode 阶段就更新，导致超预算没发出去的块永远不再发 → 永久残块。
- 带宽不够时"一页一页刷"的观感，本质是数据量太大，只能靠降色深解决。

- 可以用命令行编译验证：
  `cd obj && PATH=.../MounRiver_Studio3/.../risc-v embedded gcc/bin:.../Build_Tools/Make/bin:$PATH make all -j8`
