## task6 串口投屏：改 16 色 4bit + PackBits，去掉声音
- 用户砍掉声音（"扬声器输入的东西应该错了"），并要求"一秒一帧、每块尽量压缩"。
- 方案：4bit 索引（16 色，每帧中位切分自适应调色板 32B）+ PackBits；
  全屏 73.6KB 原始 -> 实压 20~40KB -> 0.2~0.5s 一帧。
- 图块队列 16 格 × 512B（存 4bit 索引，不是 RGB565，省一半）。
- 踩坑：块级差分时 prev 在 encode 阶段就更新，超预算没发出去的块永远不再发 -> 永久残块。改成每帧整屏重发。

## ADC / DMA 资源冲突（用户反馈"mic 的 adc 跟别的串了"）
- 根因：adc.c（软件触发，MIC 用）和 adc_dma.c（T3_TRGO + DMA，示波器/FFT 用）抢同一个 ADC1，
  谁后 init 谁生效，且都不还原。
- 已改：
  1. adc.c 的 adc_convert_once() 加 5ms 超时 + 自愈（超时就关掉 DMA/外部触发、重新 adc_init）；
  2. adc_dma 增加 adc_dma_channel_set()/get()，默认仍 PB1；
     task_fft 里 `#define FFT_ADC_CH MIC_CH_1` + fft_init 之前切通道
     （原来 FFT 页写着"麦克风频谱"，实际采的是示波器的 PB1，用户很生气）。
- 教训：ADC1/DAC/TIM2/TIM3/TIM10 都是多套驱动共用，teardown 只"停"不"还原"就会互相影响。

## 扬声器改成真正的音乐播放（DAC + DMA 实时合成）
- dac.c 新增 dac_stream_buf(&len)，把内部 512 点缓冲借给 audio.c（0 额外 RAM）。
- audio.c 新增 audio_note_t + audio_music_start/pump/stop/playing/index：
  相位累加器 + 256 点 Q15 正弦表 + 线性插值，8kHz，每 10ms 补样本。
- task_speaker 重写：两只老虎 / 小星星两首，K1 换歌 K2 播放 K3 音量。
- 踩坑（用户报"杂音像脉冲，跟着音符走"）：
  * s_fade_in 在 start 里设了之后从不清零 -> 每个音符前 20ms 都淡入，
    p=0 时 amp=0 -> 每个音符边界一次满幅跳变（1432 码值）;
  * 旧版收尾算到 1/80 而不是 0，也是边界台阶。
  * 最终方案：**音符之间不做幅度调制、只换频率，相位累加器连续**；
    淡入/淡出改成"逐个音"属性（只在整曲开头/休止后/最后一句）；
    同音重复才插 12ms V 形凹口；休止符直接输出中点。
  * 用 Python 1:1 复刻合成逻辑逐样本验证：修复前最大跳变 1432（满幅），
    修复后 493 ≤ 440Hz 正弦自身斜率 495。
